# VR EduSpace — Interactive Learning Platform

## Game Overview
VR EduSpace is a standalone VR educational application for students covering core STEM subjects (Math, Physics, Chemistry) through immersive, interactive episode-based lessons. The core loop has learners select a subject, work through structured concept-explanation and guided-interaction episodes, complete micro-assessments, and track mastery on a personal progress dashboard. What makes it unique is its focus on spatial learning — manipulating 3D objects, running simulations, and visualising abstract concepts in a calm, minimal VR environment that prioritises content clarity over spectacle.

## Problem / Opportunity
Traditional 2D educational apps (Khan Academy, Brilliant) cannot deliver the spatial, hands-on manipulation that makes abstract STEM concepts viscerally understandable. VR hardware is now mainstream enough (Meta Quest 3, Quest 2) to reach students without requiring a PC tether. There is a clear gap for a well-designed, curriculum-aligned VR learning tool that feels polished enough to hold a student's attention without the cognitive overload of over-themed edutainment apps. The opportunity is to own the premium VR STEM learning space before it becomes crowded.

## Target Players
- **Secondary / High School Students (13–18)**: Moderate–high tech familiarity, own or have school access to a VR headset, struggling with abstract STEM concepts (algebra, kinematics, molecular chemistry) and looking for a more engaging alternative to textbooks or 2D video lessons.
- **Self-Directed Adult Learners (19–35)**: College students or early-career professionals revisiting STEM fundamentals; high tech literacy; want structured, efficient learning they can complete in short sessions; value progress tracking and clear skill-proficiency feedback.

## Game Design

### Core Gameplay Loop
1. User launches app → lands in the calm Home Environment with quick-access panels.
2. User selects a Subject (Math / Physics / Chemistry) from the Subject Selection carousel.
3. User browses Episodes inside the subject, filtered by chapter, difficulty, or recommended path.
4. User opens an Episode Detail View → reviews objectives, prerequisites, and estimated time → presses Start or Resume.
5. User moves through the in-episode structure: Concept Explanation → Guided Interaction → Practice Task → Checkpoint.
6. Micro-assessment (MCQ, interactive task, or "Fix the Mistake" scenario) fires after each concept chunk with instant feedback and optional hints.
7. Episode ends with a Completion Screen showing score, mastered concepts, weak areas, and time spent.
8. User is routed to Next Episode, Retry, or Back to Subject; progress is saved and the Progress Dashboard updates in real time.

### Game Mechanics
- **Gaze + Tap / Controller Select**: Primary input for all menu navigation; gaze activates hover state on tiles after 1.5s dwell time; controller trigger or hand pinch confirms selection. [Assumed: support both 6DOF controllers and hand-tracking]
- **Object Manipulation in Lessons**: Drag, rotate, and assemble 3D objects using controller grab (grip button) or hand-tracking pinch-and-hold; physics-based snapping within 5cm of correct position triggers confirmation feedback.
- **Graph Interaction (Math)**: Move control points on a 3D Cartesian graph with direct grab; adjusting slope or intercept animates the equation overlay in real time with a 0.05s update lag cap.
- **Variable Simulation (Physics / Chemistry)**: Sliders or dial controls change simulation variables (e.g., velocity, temperature); scene reacts with frame-accurate particle or object behaviour within the same rendered frame.
- **MCQ Answer Input**: Floating answer panels appear spatially around the user; selection via gaze+trigger or hand-point; wrong answers trigger a red shake animation + hint panel; correct answers trigger a green pulse + audio cue.
- **Numeric Input**: Virtual keyboard or thumbstick scroll-wheel number selector; [Assumed: thumbstick numeric input preferred to avoid virtual keyboard fatigue in VR].
- **Scroll / Browse**: Episode list scrolls via swipe gesture (hand tracking), controller thumbstick scroll, or hand-grab-and-drag on the panel surface.
- **Wrist UI**: Left-wrist flip gesture opens quick-access overlay (Profile, Progress, Settings, Jump Menu); closes on re-flip or trigger press away from panel.
- **Seated + Standing Mode Toggle**: Recalibrates floor level and comfortable UI placement radius; selectable in Settings; [Assumed: default is Seated mode to maximise accessibility].
- **Motion Comfort Options**: Vignetting toggle during any locomotion or spatial transitions; snap-turn in 30° increments as default; smooth-turn optional.

### Progression System
- **Episode Lock/Unlock**: Episodes unlock sequentially within a chapter by default; prerequisite episodes must be completed at ≥60% checkpoint accuracy to unlock the next. [Assumed: 60% threshold — confirm with curriculum designer]
- **Completion Status Tags**: Each episode tile displays one of four states — Locked, Not Started, In Progress, Completed.
- **Skill Proficiency Score**: Per-subject proficiency score (0–100) calculated as weighted average of checkpoint accuracy across all completed episodes; displayed on Progress Dashboard as a radial fill gauge.
- **Difficulty Tiers**: Three tiers per subject — Beginner, Intermediate, Advanced; Intermediate unlocks after completing ≥50% of Beginner episodes in a chapter.
- **Bookmarks**: User can star any episode or concept card; bookmarked items surface in a dedicated "Saved" section accessible from wrist UI.
- **Adaptive Recommendation Engine** *(Optional Enhancement)*: After episode completion, next-episode recommendation is surfaced based on weak-area heatmap data and curriculum graph; displayed as a "Recommended for You" card on the Home screen.

### Win / Lose Conditions
- **Success State**: Episode completed with ≥80% checkpoint accuracy → "Mastered" badge awarded; concept added to Mastered list on Progress Dashboard.
- **Partial Completion**: Episode completed with 60–79% accuracy → "Completed" status; weak concept areas flagged on dashboard heatmap.
- **Retry Trigger**: Checkpoint score below 60% → end-of-episode screen prompts Retry with weak concepts highlighted; no hard block, user can still proceed but episode marked as "Needs Review."
- **No punitive fail state**: There are no lives, timers, or penalty mechanics — this is an educational tool; failure surfaces as diagnostic feedback only.

## Visual & Audio Direction

### Art Style
Minimal, clean spatial UI aesthetic — think the clarity of Apple Vision Pro's visionOS interface blended with the calm geometry of Monument Valley. Colour palette: off-white and light grey environment surfaces, subject-coded accent colours (Math = blue, Physics = orange, Chemistry = green), with high-contrast white text on dark frosted-glass UI panels. All environments are 3D with no heavy theming — a neutral floating room or soft void space with subtle ambient depth. Tone is calm, focused, and professional — not childish or gamified beyond necessary feedback cues.

### 3D / 2D Assets Required

**Characters:**
- No character avatars required in v1. [Assumed: AI Tutor Enhancement in v2 would introduce an avatar]

**Environments:**
- **Home Environment**: Minimal neutral 3D room — smooth floor plane, soft ambient light, floating UI panel architecture; one master scene.
- **Subject Environment Variants** (×3 — Math, Chemistry, Physics): Subtle environmental colour-shift and thematic prop set (e.g., floating equations for Math, molecular models for Chemistry, motion vectors for Physics) layered on top of shared base environment; not full scene rebuilds.
- **Episode Learning Space**: Clean void/room with subject-appropriate interactive 3D stage (e.g., graph grid for Math linear equations, lab bench for Chemistry, physics track for kinematics).
- **Completion Screen Environment**: Soft particle confetti burst in a neutral space; no separate 3D scene — overlay on existing learning space.

**UI Elements:**
- Subject tile card (icon, completion bar, episode count, last-accessed label) — ×3 subjects
- Episode tile card (title, duration badge, difficulty tag, lock/unlock state, completion ring)
- Episode Detail View panel (objectives list, prerequisites, time estimate, progress bar, Start/Resume/Bookmark CTAs)
- Wrist UI panel (profile avatar, progress ring, settings icon, quick-jump menu)
- Checkpoint question panel (MCQ layout, numeric input layout, "Fix the Mistake" layout)
- Episode Completion screen panel (score dial, mastered concepts list, weak areas list, time spent, action buttons)
- Progress Dashboard panels (subject progress bars, episode node-graph map, skill proficiency radial gauge, heatmap grid)
- Hover/preview tooltip panel for subject tiles
- Hint panel (triggered on wrong answer)
- Loading/transition fade overlay

**VFX:**
- Correct-answer green pulse + radial ring expand on selection panels
- Wrong-answer red shake + brief desaturate on answer panel
- Smooth spatial transition fade (black or white fade, 0.4s) between Home → Episode and Episode → Completion
- Subject tile hover glow (soft bloom edge light on tile border)
- Graph line animate/draw shader for Math interactions (line redraws in real time as points are moved)
- Particle system: molecule bond assembly (Chemistry sim)
- Particle system: physics trajectory arc render (Physics sim)
- Completion screen: soft confetti particle burst (500–800 particles, 3s duration, auto-despawn)
- Wrist UI open/close: scale-up from wrist origin with ease-out curve (0.15s)
- Adaptive recommendation card pulse glow (Home screen)

### Audio
- **Music**:
  - Home / Navigation BGM: 1 looping ambient track — calm, minimal, low-frequency pad-based, no melody distraction. (~3 min loop)
  - Learning Session BGM: 1 looping low-intensity focus track per subject (×3 tracks) — subtle rhythmic texture, fades to near-silence during checkpoint questions. (~4 min loops)
  - Episode Completion Sting: 1 short positive resolution cue (3–5 sec, non-looping)
  - [Assumed: all music adaptive using Unity's Audio Mixer snapshots — duck BGM during voice/instruction if AI Tutor is added in v2]

- **SFX**:
  - UI tile select click (soft, satisfying, non-aggressive)
  - UI tile hover enter / hover exit (subtle high-frequency tick)
  - Object grab (controller haptic + soft whoosh)
  - Object snap-to-correct-position (satisfying click + haptic pulse)
  - Correct answer chime (short, positive)
  - Wrong answer tone (soft low buzz — not harsh)
  - Hint panel open (soft chime)
  - Bookmark toggle on / off
  - Wrist UI open / close (soft spatial pop)
  - Progress bar fill increment tick
  - Episode unlock sound (soft ascending two-note)
  - Scene transition whoosh (tied to fade)
  - Variable slider scrub (subtle continuous low tick while dragging)

## Technical Specifications
- **Engine**: Unity 2022 LTS (minimum) — recommend Unity 6 LTS for XR performance improvements [Assumed: confirm with tech lead]
- **Platform**: Meta Quest 2 / Quest 3 (primary); PC VR via SteamVR (OpenXR) as secondary [Assumed: Quest standalone is primary deployment target]
- **Target Frame Rate**: 72fps minimum on Quest 2; 90fps target on Quest 3; never drop below 72fps — frame drops in VR cause motion sickness
- **Rendering**: Single-pass instanced stereo rendering; Fixed Foveated Rendering (FFR) enabled on Quest 2
- **Orientation**: VR headset — N/A (immersive mode, 360° space)
- **Min Device Spec**: Meta Quest 2 (6GB RAM, Snapdragon XR2); Android 10 base OS on Quest
- **Multiplayer**: No
- **Input System**: Unity XR Interaction Toolkit (XRI) 2.x+ with OpenXR plugin; support 6DOF controllers + Meta Hand Tracking SDK
- **Hand Tracking**: Meta XR Hand Tracking SDK via OpenXR; fallback to controller input if hands not detected
- **Backend Services**:
  - Cloud Save (user progress, episode completion state, bookmarks, skill scores)
  - User Authentication (account creation, login — email/password + optional OAuth)
  - Analytics (session length, episode completion rate, checkpoint accuracy per episode, drop-off points)
  - Leaderboards: Not required in v1
